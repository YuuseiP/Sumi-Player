# 听歌喜好：设备名称表、规则与设置

已接入“我的 → 软件设置 → 听歌喜好”独立选项卡。六类开关默认关闭，启用后自动保存并立即影响前台和原生后台队列，无需扫描。每类提供命中数量、搜索预览、原文依据，以及逐首“始终保留／单独排除／跟随规则”。歌曲菜单也提供单独排除入口，可选在曲库列表隐藏排除项。

`analyze_library.py` 是只读目录采集与离线分析工具；`rules-draft.json` 保留最初文件名，现为 APK 构建使用的版本标记规则。`prepare-preferences.cjs` 将规则和现有角色原名字典编译成 assets；`PreferenceRules.java` 分类后将解释随曲库摘要提供给前端，前端不另写一套正则。用户配置单独保存在 `ui.preferences`，纳入原有资料备份和导入校验。

## 规则处理顺序

1. 保留原文，在比较副本上做 NFKC 和大小写统一；不改写文件、歌曲标签或曲目 ID。
2. 对标题、文件名分别识别，并保存命中字段、规则 ID 和具体文本。优先使用真正的标题；本次系统元数据仅作分析证据。CUE 逻辑曲目接入时使用播放器已解析的子曲目标题。
3. 标记必须出现在版本说明末尾、括号闭合前，或音质／来源附注前；`Instrumental Journey`、`Off Vocal Collection_01_通常曲` 不能凭正文单词命中。文件名可能重复包含专辑标题，需继续查找后面的真实版本标记。
4. 若标题和文件名类别冲突，列入待核对列表，不能静默扩大排除。只在用户主动启用的类别中评估；每首歌必须能解释为什么被排除。
5. 逐首“始终保留”优先于所有规则；逐首“排除”优先于类别开关；其后才检查已启用的类别。收藏不自动等于白名单，独立保存逐首例外。

草案配置 `enabled_rules` 为空。普通用户使用中文开关，不要求填写正则。自定义规则可后续提供“标题包含／标题后缀”，必须先显示命中预览、数量及撤销入口，避免把任意正则作为首版必要能力。

## APK 行为

入口位于“我的 → 软件设置 → 听歌喜好”，与“通用设置”并列。首次打开所有开关关闭。每类开关下方提供命中数量和预览入口，关闭开关时也能预览；切换开关立即保存。命中数表示该类全部候选，不随逐首保留减少；顶部“已排除”是应用例外后的去重总数。

正式分类优先使用播放器的标题；仅标题为空才用文件名分类。文件名中出现标题没有的版本类别时只列入待核对、保留原文依据，不静默扩大排除。CUE 只判断子曲目标题，不判断整盘文件名。离线目录分析中使用的是系统缓存标题，和应用已有逻辑曲库的统计范围不同。

默认影响自动队列、随机播放、上一首／下一首及歌单连续播放。曲库仍能搜索这些歌曲，显示排除原因；“同时在曲库隐藏”作为额外开关。原歌单成员、收藏和历史保留原 ID。手动点击被排除歌曲可明确选择仅播放一次或始终保留，单次播放不把整批被排除歌曲放回自动队列。

启用规则时正在播放的歌保留到结束，按新规则生成后续队列；候选全被排除时显示空状态并停止，不能回退到整库。取消规则、重新扫描和更改标题后重新计算候选；关闭规则应能完整恢复可播放范围。暂停、位置和声音设置沿用现有持久化边界。

| 接入位置 | 必须处理的行为 |
|---|---|
| `android/ui/app.js` 的状态、持久化、列表及 `queueIndices()` | 保存开关和逐首例外、预览、可选隐藏、前台队列与缓存失效 |
| `android/app/src/main/java/cn/yuusei/m3x/PlaybackService.java` 的 `syncQueue()` | 原生后台、息屏、耳机切歌与整库随机都执行同一排除决策；把规则修订号纳入队列缓存条件 |
| 原生曲库摘要／专用规则评估器 | 扫描完成或标题变化后重新分类；所有前后台入口读取相同版本规则和逐首例外 |
| `android/native-bridge.js` 与现有 `ui` 设置备份 | 在完整 UI 设置中保留喜好；逐字段验证导入数据，不清空其他设置 |
| `android/ui/index.html`、`styles.css` 与 Android assets 构建 | 正式界面和资源入口；按照 `android/APPEARANCE.md` 在原签名真机验收 |

现有 `hidden` 保留逐首隐藏用途，喜好配置单独存储在 `ui.preferences`：`{schema: 1, enabledCategories: [], keepTrackIds: [], excludeTrackIds: [], hideInLibrary: false}`。完整配置和单次播放状态共同纳入原生队列缓存条件。原始选择队列独立保留，后台切歌不会把过滤后的队列覆盖到原选择，关闭规则可恢复。

“仅播放一次”只在服务内存中保留当前歌曲，切离或播放结束后从自动队列移除；不写入长期例外。正在播放时启用规则采用同样的当前歌曲宽限，单曲循环临时解除，只有这一首时播完停止。重启不会恢复单次豁免。收藏不自动豁免，逐首始终保留优先级最高。

真机验收及截图见已忽略的 `android/captures/preferences-20261031/`；发布 APK 与复核入口见 [验收记录](../PREFERENCES.md)。测试恢复原有 UI、音频、统计、扫描状态、队列和位置，不改写歌曲。硬件耳机按键、实际资料文件导入导出和用户主动重新扫描未在此验收中操作，分别共用原生过滤队列、完整 UI 备份及曲库重新分类入口。

## 复现

在仓库根目录运行，全程使用现有 ADB，只读取设备：

```powershell
python -X utf8 '.\android\preferences\analyze_library.py' --collect --serial a6840768
```

仅重新分析已保存的名称表，无需连接设备：

```powershell
python -X utf8 '.\android\preferences\analyze_library.py' --input '.\android\local-fixtures\preferences-20261031-133706'
python -m unittest discover -s '.\android\preferences' -p 'test_*.py'
```

脚本只允许把结果写入 `android/local-fixtures/` 的子目录。原始名称、元数据和明细保持 Git 忽略；分析工具、通用规则与本说明可随源码管理。
