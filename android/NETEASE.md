# 网易云音乐 tab 与自动歌词匹配

日期：2026-11-15。基于 0.6.0。

## 本地 / 网易云 双模式

首页标题本身就是来源页签：本地曲库标题为「**曲库** 网易云」，网易云发现页为「曲库 **网易云**」，点灰色的那个即切换（记忆在 WebView localStorage）。两个「我的」页都只有普通标题。两种模式共用播放页、队列、歌词、设置：

- 本地模式：导航「曲库 / 播放 / 我的」，与原来一致；网易云导入的曲目不出现在本地曲库、收藏、计数中。
- 网易云模式：导航「发现 / 播放 / 我的」。
  - 发现：一个搜索栏（聚焦显示热搜，提交后同时给出歌单与单曲）；入口「每日推荐 / 私人FM / 我喜欢」；推荐歌单（登录后为个性化推荐）。排行榜已移除（2026-11-16）。
  - 换一批：在发现页顶部下拉（阻尼跟手，超过 64 px 松开）或点推荐歌单标题右侧「换一批」，换成 9 个尚未展示过的歌单。原生操作 `more-playlists` 先从每次随机重抽的 `/personalized/playlist`（30 个）中取未展示的，不足时按批次翻 `/playlist/list`（全部 · 热门，循环前 600 个）；已展示的歌单编号由页面记录并随请求排除。
  - 歌单详情页（歌单、每日推荐、专辑、歌手热门、相似歌曲、最近常听共用）：封面、简介、播放全部、编号曲目列表、正在播放高亮。
  - 我的：头像、昵称、黑胶等级与到期日、账号等级、累计听歌；我喜欢 / 最近常听 / 私人FM；创建与收藏的歌单；在线音质、软件设置、听歌统计、清理缓存曲目、退出登录。
  - 播放页：网易云歌曲的红心按钮同步网易云「喜欢」，「添加到歌单」改为收藏到自己的网易云歌单，歌手/专辑链接打开网易云歌手页与专辑页；歌曲菜单增加喜欢、评论（精彩+最新）、相似歌曲。
  - 心动模式：播放网易云歌曲时，播放顺序按钮循环为 列表循环 → 随机 → 单曲循环 → **心动模式**。进入时保留当前歌曲，以它为种子把后续队列换成推荐；按钮显示心动图标，再点一次回到列表循环。
  - 私人FM：从发现页或我的页进入。FM 期间播放顺序按钮变为「不喜欢」（垃圾桶，跳过并减少推荐）。
  - 两种电台运行时，播放页格式文字位置显示「私人FM ×」或「心动模式 ×」标签，点击退出；播到倒数第二首时自动续取；手动播放其他歌曲即退出。网易云列表里的随机播放只在该列表内随机。

## 账号与接口

功能：

| 功能 | 说明 |
|---|---|
| 登录 | 扫码登录（网易云音乐 App 扫描）或「网页登录」：应用内浏览器（`NeteaseLoginActivity`）打开网易云官方登录页 `music.163.com/m/login`，用户在官方页面登录，出现 `MUSIC_U` Cookie 后自动取回并登录，随即清空该浏览器的 Cookie。应用不读取、不保存账号密码。Cookie 用 Android 密钥库 AES-GCM 加密保存在应用私有设置 `netease` 中，只发送给 `music.163.com` / `interface3.music.163.com`。 |
| VIP 状态 | `w/nuser/account/get` 的 `vipType`，再用 `music-vip-membership/front/vip/info` 读取黑胶 SVIP / 黑胶 VIP / 音乐包的到期时间和等级；后者失败时退回 `vipType`。 |
| 搜索 | eapi `/api/cloudsearch/pc`（匿名 weapi `cloudsearch/get/web` 实测返回风控码 50000005，仅作后备），每页 30 首，最多加载 300 首；无版权（`privilege.st < 0` 或 `noCopyrightRcmd`）的歌曲灰显不可播放，VIP 歌曲带标记。 |
| 每日推荐 / 我的歌单 | 需登录。歌单曲目通过 `v6/playlist/detail` 取 `trackIds`，再分批 400 首调用 `v3/song/detail`；单个歌单最多 3000 首。 |
| 播放 | 点击歌曲把当前列表中可播放的歌曲导入曲库（目录「网易云音乐」，URI `m3xnetease://song/<id>`），并按该列表设定播放队列。播放地址在 ExoPlayer 打开数据源时才通过 eapi `song/enhance/player/url/v1` 解析（失败时退回 weapi），按地址有效期缓存最长 15 分钟。 |
| 音质 | 标准／较高／极高／无损／Hi-Res，默认无损；非会员由平台自动降级。仅能试听片段（`freeTrialInfo`）的歌曲会拒绝播放并提示需要 VIP，不把 30 秒片段当整曲。 |
| 移除导入 | 「移除已导入曲目」从曲库删除导入的网易云歌曲（保留正在播放的）。曲目 ID 由歌曲编号确定，再次播放时收藏和歌单记录恢复。 |

封面与头像经 `https://m3x.local/netease-cover/?u=` 代理，只允许 `*.126.net` HTTPS 地址，缓存在 `cache/netease-covers`（超过 600 个清理到 500 个）。

### 边界

- 接口是网易云网页/桌面端的非公开接口（weapi / eapi 加密封装），没有稳定性保证；风控（-460 / 8821）时提示改用网页登录或稍后再试。
- 登录失效（301）提示重新登录；退出登录清除保存的 Cookie。
- 导入的网易云歌曲出现在本地曲库「全部」中；扫描不会删除它们。
- 网易云歌曲不能「写入歌曲文件」，可在应用内保存歌词。
- 二维码由 ZXing core 3.5.3（Apache-2.0）在本机生成。

## 自动歌词匹配

播放的歌曲没有同步歌词（无已采用歌词、下载 LRC、同名 LRC、内嵌同步歌词）且联网时，约 1.2 秒后自动：

1. 用「曲名 + 歌手」同时搜索 QQ 音乐和网易云音乐；都没有合格候选时再只用曲名搜索一次。
2. 只保留**平台时长与本地时长相差 ≤1000 ms**、曲名一致（全等 / 去括号后相等 / 互相包含）、且候选曲名没有本地曲名未标注的版本词（Live、Remix、Off Vocal、伴奏、TV Size 等）的候选。
3. 排序：曲名精确度 > 歌手一致 > 专辑一致 > 时长差更小。按序最多取 4 个候选的歌词，第一个含有效同步原文、不是「纯音乐」占位的候选被自动采用（含平台译文）。
4. 网易云 tab 导入的歌曲直接按其网易云歌曲编号取词，且不使用 24 小时无结果缓存。

网易云取词：已登录时先用账号 Cookie 走 eapi `/api/song/lyric/v1`（部分版权受限的发行条目对匿名请求返回空 `lrc`），为空再回退匿名 `/api/song/lyric`。两者都为空时报「网易云没有提供此版本的歌词」；QQ 返回空歌词时报「QQ 音乐没有收录此版本的歌词」。

「搜索／更换歌词」面板：

- 网易云 tab 的歌曲默认来源为网易云音乐；未采用歌词时打开面板即自动搜索，当前歌曲本身（按歌曲编号）总排在候选首位并标「当前网易云歌曲」，有同步歌词时自动选中预览（仍需手动保存）。
- 搜索后在后台逐个预取候选歌词（同一工作线程，用户点击的候选优先），在每行标注「同步原文＋译文 / 同步原文 · 无译文 / 无同步歌词」，无歌词的候选置灰。此前「候选没有同步原文」的偶发报错来自这类本身无歌词的发行条目（实测 QQ 部分 M@STER VERSION 条目、网易云部分版权受限条目），不是网络随机失败。预取遇到限流等非「无歌词」错误即停止，不重试。

自动结果保存为普通的逐曲选择（标注 `auto` 和时长差），可在「搜索／更换歌词」中替换；手动保存后去掉自动标记。自动匹配永不覆盖已采用的歌词，搜索期间用户手动采用的结果优先。两源都正常完成但无合格候选时，24 小时内不再重复查询（换标签/文件后失效）；断网、超时等错误不写入此缓存。

「我的 → 软件设置」中「联网自动匹配歌词」可关闭此功能（默认开启）。

### 网易云歌词搜索修复

原歌词搜索使用的明文 `/api/search/get/web` 现在返回加密字符串，`result.songs` 为空，网易云来源实际拿不到候选。已改为明文 `/api/cloudsearch/pc`，并同时解析新（`ar`/`al`/`dt`）旧（`artists`/`album`/`duration`）两种字段。

### 冷启动：复用已分类目录

`library.json` 保存的本就是分类与听歌喜好标注后的曲目。旁边新增 `library.classified`，记录产生它的规则指纹（内置分类、喜好规则资源的哈希 + APK 安装时间）。启动时指纹一致就直接采用已保存的曲目，只把歌手条目重新指向共享实体对象（`ArtistClassification.relink`，也省内存），不再逐曲定位存储地址和重新分类；任何曲目缺少分类结果或引用了已删除实体时，整体回到完整分类。写目录前先删除标记，写完再写标记，中途崩溃只会导致下次多做一次完整分类。扫描完成时改为保存分类后的列表。

| 冷启动（5213 首，M3X 实测） | 之前 | 之后 |
|---|---|---|
| 曲库就绪 | 9.2 s | 2.5 s |
| 界面可操作 | 11.4 s | 4.4 s |

每次安装新 APK 后的第一次启动仍走完整分类（约 9 s）并写入标记，之后的启动走快速路径。剩余耗时主要是解析 `library.json`（约 2 s）。
